# talos_hack

This is the **canonical, tool-agnostic rulebook** for everyone working in this repo, human or AI
agent (Claude Code, Codex, Cursor, and others). Codex and Cursor read `AGENTS.md` by default;
Claude Code imports it from `CLAUDE.md`. Edit shared rules here, in one place.

Software and tests for the Talos robot built at a physical AI hackathon. The robot is driven by
Feetech STS/SMS serial bus servos daisy-chained on one half-duplex UART bus.

- **GitHub:** https://github.com/Annnnya/talos_hack
- **Team repo:** several people push here. Never rewrite shared history.

## Stack

- **Language:** Python (>= 3.10)
- **Package managers:** uv (`uv sync`, `uv run`, `uv add`) and pixi (`pixi install`,
  `pixi run`, `pixi add`) side by side - never pip. Both read `pyproject.toml`. When you change
  dependencies, update both lockfiles (`uv lock` and `pixi install`) and commit `uv.lock` and
  `pixi.lock` together. CI checks both
- **ROS 2 (planned):** Jazzy via RoboStack, through pixi only (`pixi.toml`, channel
  `robostack-jazzy`). Python stays on 3.12 to match Jazzy
- **Servo SDK:** `ftservo-python-sdk` (official Feetech SDK, imported as `scservo_sdk`, provides
  `sms_sts`). Do not add `feetech-servo-sdk`: it is an older fork without `sms_sts` and installs the
  same module name, so the two conflict
- **Lint and format:** ruff (`uv run ruff check .`, `uv run ruff format .`, or `pixi run lint`,
  `pixi run fmt`)
- **Tests:** pytest (`uv run pytest` or `pixi run test`)
- **Build backend:** hatchling (`pyproject.toml`)

## Layout

```
src/talos_servo/   # importable package: bus wrapper, register constants, CLI
tests/             # pytest suite only - must run without hardware
```

- Reusable logic goes in `src/talos_servo/`, not in one-off scripts
- `tests/` contains automated tests only. Scripts that move real servos are CLI commands, not tests
- Tests must never touch a serial port. Use the fake SDK objects in the test suite

## Hardware safety

Code in this repo moves physical motors. Treat every change as if the robot is on the bench next to
someone's hand.

- Every code path that starts a motor must stop it in a `finally` block or context manager exit,
  including on `KeyboardInterrupt`
- Default speeds and accelerations must be low. Higher values are opt-in via explicit arguments
- Never hardcode serial ports, baud rates or servo IDs in logic. Take them from CLI options,
  environment variables or config with safe defaults
- Do not write EEPROM settings (servo ID, baud rate, operating limits, offsets) without the user
  explicitly asking. A wrong baud or ID write can make a servo unreachable
- Check every SDK result (`comm_result`, `error`) and fail loudly. Do not silently ignore errors
- Agents must not run commands that move hardware unless the user asks for it in that session

## Code style

- Type hints on all public functions; small focused modules
- Name register addresses and magic numbers as constants (or reuse the `SMS_STS_*` constants from
  the SDK). No bare numbers like `40` in logic
- Comments only when the WHY is non-obvious
- **ROS 2 nodes:** every file under `src/` that defines a ROS 2 node ends in `_node.py`
  (e.g. `arm_controller_node.py`), and only node files use that suffix
- **No assistant or tool attribution** anywhere: no "Generated by", "Made with", badges, bylines,
  or `Co-Authored-By:` trailers in code, docs, commits, PR descriptions or issues

## Writing style

- **No em dashes.** Use a regular hyphen (-) if a separator is needed. This applies to commit
  messages, PR descriptions, code comments, docstrings and docs.

## Git and PR workflow

**Everything goes through pull requests.** No direct pushes to `main`, for anyone.

1. Open (or pick) a GitHub issue describing the change
2. Create a branch named `type/issueNumber-short-description` (e.g. `feat/3-arm-ik`,
   `fix/7-ping-timeout`) in its own worktree (see below)
3. Commit in small logical steps using Conventional Commits
4. Push and open a PR that references the issue (`Closes #N`). Fill in what changed, why, and how
   it was tested (including whether it was tried on hardware)
5. At least one teammate reviews. CI checks (ruff, pytest) must pass once CI exists
6. **Squash merge** into `main` (the only merge strategy). Delete the branch after merge

Stacked PRs (a branch based on another open PR) are fine when changes depend on each other. Say so
in the PR description and merge in order.

### Commit messages

Conventional Commits. Every commit message must:

- Be a single sentence, lowercase, no period at the end
- Use the format `type: short description`
- Never include AI/tool signatures, co-author lines or attribution footers

**Allowed types:** `feat` (new capability), `fix` (bug fix), `chore` (tooling, config,
dependencies), `style` (formatting, no logic change), `refactor` (restructuring without behavior
change), `docs` (documentation), `perf` (performance), `test` (adding or updating tests).

```
feat: add monitor command that streams position and speed
fix: stop all servos when keyboard interrupt hits during spin
chore: switch servo dependency to ftservo-python-sdk
test: cover servo bus result checking with fake sdk
```

## Worktree convention

Every non-trivial change is developed in a dedicated git worktree so branches never share a dirty
working tree.

Worktrees live in a gitignored `worktrees/` folder at the repo root. One folder per branch type,
and inside it the branch leaf (the part after `type/`). Branch `feat/5-gripper` checks out at
`worktrees/feat/5-gripper`.

```
talos_hack/                    <- main repo folder, stays on main, only used to pull
talos_hack/worktrees/          <- gitignored
  feat/
    5-gripper/                 <- branch feat/5-gripper
  fix/
    7-ping-timeout/            <- branch fix/7-ping-timeout
```

Create (always from the main repo folder, never from inside another worktree):

```
git switch main && git pull
git worktree add -b feat/5-gripper worktrees/feat/5-gripper main
```

Each worktree has its own `.venv` and `.pixi/`; run `uv sync` or `pixi install` inside it.

Remove after the PR is merged:

```
git worktree remove worktrees/feat/5-gripper
git branch -D feat/5-gripper
```

(`-D` is needed because squash merges do not keep the branch commits in `main`.)
